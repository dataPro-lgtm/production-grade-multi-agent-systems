# アーキテクチャ決定記録：マルチエージェントを採用するか

このページをコピーして新しいADRを作成し、ファイル名を `ADR-NNN-简短标题.md` とします。

## ステータス

提案 / 承認済み / 却下 / 置き換え済み

## 背景

事業目標、ユーザー、タスクの種類、現在のボトルネック。

## 制約

レイテンシ、コスト、権限、コンプライアンス、データ、チーム、運用上の制約。

## 候補案

1. 決定論的ワークフロー。
2. LLM拡張ワークフロー。
3. 単一Agent。
4. マルチエージェント。

## 決定

どの案を選ぶか。また、それが要件を満たす最もシンプルなアーキテクチャである理由。

## 実際の境界

ドメイン、データ、ツール、権限、状態、障害、スケーリング、組織上のオーナーシップという各境界を説明する。

## コスト

増加が見込まれるモデル呼び出し、レイテンシ、Token、状態同期、テスト範囲、運用の複雑さ。

## 検証

どの Golden Dataset、指標、ベースライン、リリースゲートを用いて効果を証明するか。

## ロールバック

期待した効果が得られない場合やリスクを制御できない場合に、よりシンプルなアーキテクチャへどのようにダウングレードするか。
