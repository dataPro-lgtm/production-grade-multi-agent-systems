# Agent定義カード

Agentを作成する前に、まずこのカードを記入してください。明確に回答できない項目がある場合、通常は境界設計がまだ完了していません。

| フィールド | 記入内容 |
|---|---|
| Agent名 | 責任領域に基づいて命名し、単なる人格名は避ける |
| ビジネス目標 | 誰のどのような問題を解決するか |
| 成功基準 | 完了し、かつ正しいことをどう判断するか |
| 許可する入力 | 受け入れるタスク、コンテキスト、アイデンティティ |
| 許可する出力 | 返すべき構造とエビデンス |
| 許可するツール | 呼び出し可能なツールと、その読み書き属性 |
| データ境界 | アクセス可能なデータ |
| 権限境界 | 禁止するアクション、または承認が必要なアクション |
| 状態 | 永続化が必要なタスク状態 |
| 予算 | 時間、Token、費用、再試行回数の上限 |
| 終了条件 | 成功、失敗、人間への引き継ぎ、回答拒否の条件 |
| 評価 | 検証に使用するデータセットと指標 |
| Owner | 保守、承認、障害対応の担当者 |

## 最小構成の例

```yaml
name: refund-analysis-agent
goal: 指定した範囲における返金率の変化の主要因を特定する
success:
  - すべての結論にクエリエビデンスがある
  - 分母、期間、フィルター条件が明確である
allowed_tools:
  - metadata_search
  - read_only_sql
forbidden:
  - 本番データベースへの書き込み
  - 行および列レベルの権限を回避する
stop:
  - エビデンスがリリース基準を満たす
  - 予算を使い切る
  - 権限が不足している
  - 人間への確認が必要
```
