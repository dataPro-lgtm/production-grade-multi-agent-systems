# 阅读建议

这本书既可以顺序阅读，也可以作为架构和工程手册查阅。第一次接触生产级 Agent 系统，建议按十章顺序推进；正在解决具体问题时，可直接从下表进入。

## 按问题进入

| 你正在解决的问题 | 建议章节 |
|---|---|
| 不确定该用工作流、单 Agent 还是多 Agent | 第 01—03 章 |
| Tool Call 失控、状态难恢复，或 MCP 边界混乱 | 第 02、05、06 章 |
| 多 Agent 协作后出现状态冲突、证据丢失或无法收敛 | 第 03、07、08 章 |
| RAG 结果过期、冲突、越权，或无法追溯来源 | 第 04、06、07 章 |
| 系统能演示，却无法稳定部署、诊断和恢复 | 第 05、07、09 章 |
| 缺少权限、隐私、审批和红队验证体系 | 第 06、08、10 章 |
| 无法证明新模型、新 Prompt 或新架构是否更好 | 第 08、09 章 |
| 正在准备验收、发布或开源完整系统 | 第 07—10 章 |

## 按角色进入

| 角色 | 推荐路径 |
|---|---|
| 架构师 / 技术负责人 | 01 → 03 → 05 → 07 → 08 → 10 |
| AI / LLM 工程师 | 02 → 04 → 06 → 07 → 08 |
| 平台 / SRE / 安全团队 | 05 → 06 → 07 → 09 → 10 |
| 数据与知识工程师 | 01 → 04 → 06 → 08 |
| 产品技术负责人 / FDE | 01 → 03 → 07 → 08 → 10 |

## 每章怎样读

每章同时有三条线：

1. **知识线**：理解概念、原理、判断方法和不适用边界；
2. **工程线**：观察合同、状态、代码、失败路径和运行证据；
3. **迁移线**：把章节末的检查表或模板带回自己的系统。

阅读时先确认“这一章试图解决什么风险”，再看架构图中的责任和控制流；理解结论后，切换到对应的 CaseOps 固定版本运行验收。服务能够启动只是起点，真正的完成标准写在测试、评测、Trace、审计和发布证据中。
